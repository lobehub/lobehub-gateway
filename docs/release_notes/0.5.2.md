### Fixed

- **Bounded replay buffer**: replay history is now capped by encoded byte size in addition to event count, so a small number of large events can no longer let the buffer grow unbounded. Events that no longer fit are still delivered live, and replay reports a gap for them instead of silently truncating.
- **Failed socket writes**: v1 WebSockets are closed when a broadcast or replay write fails, so clients reconnect and resume rather than staying attached to a dead connection.
- **Late connections**: a v1 client that attaches after a run has finished now receives the replay stream history and the known terminal state, without re-dispatching tool requests.

### Compatibility

- No configuration changes are required. Existing event limits, ordering and replay semantics for live connections are unchanged; only clients attaching after a run completes see the new terminal-state replay.
